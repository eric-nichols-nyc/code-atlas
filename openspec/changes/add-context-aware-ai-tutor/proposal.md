# Proposal

## Why

The practice workspace has an AI tutor tab, but it only displays a placeholder. Learners need to ask questions such as “I'm stuck here” and receive guidance based on the problem and their current, possibly unsaved JavaScript without copying code into chat or generating AI traffic while typing.

## What Changes

- Replace the tutor placeholder with a problem-specific conversation, question composer, streamed replies, and explicit Send, Stop, and failure recovery controls in the existing desktop panel and mobile drawer.
- Reuse CodeMirror's existing `ProblemSession` source updates. Editing stays local; only an explicit question submission or explicit retry creates a tutor request. Each request captures the latest code once, including edits made without Run, Submit, or Save.
- Build the model context on the server from the published problem's authored statement, public examples, constraints, entry function, and applicable supplied callbacks. Add the current code, bounded recent dialogue, and only allowlisted visible execution feedback that still matches the current code/inputs.
- Add a protected same-origin tutor Route Handler and a server-only OpenAI Responses API adapter using the already configured API key. Verify Neon identity and origin before provider access; bound requests, concurrency, duration, and output. Do not forward hidden judging data or private notes.
- Keep chat and its question draft in memory for the current learner/problem visit, as requested. They survive panel closing, Notes tab switches, theme changes, and responsive remounts, but end on navigation away, reload, sign-out/account change, or quitting Electron.
- Attribute each answer to the code captured when its question was sent. Later edits neither change that request nor trigger another one; the next question captures the newest code.

The initial slice covers the thirteen published JavaScript practice problems in the browser and online Electron. The approved tutoring style is concise, hint-first guidance, with full solutions only when explicitly requested.

Deferred: saved chat history, cross-device chat, automatic keystroke analysis, code completion, editor changes generated by AI, agent tools/code execution, private-note retrieval, attachments, voice, external retrieval, and Learn curriculum.

## Capabilities

### New Capabilities

- `problem-ai-tutor`: Question-triggered tutoring grounded in the current problem and code, with session-only conversation, authenticated provider access, and honest request/answer lifecycle.

### Modified Capabilities

None. The main OpenSpec capability inventory is currently empty. The completed personal-notes change explicitly excludes notes from tutor context; this proposal preserves that requirement.

## Impact

- Extend `ProblemExperience` and the generic learning shell with a tutor content slot, following the existing Notes composition. Own problem-specific tutor components, state, contracts, and server modules in `apps/web/src/features/problems/`.
- Add `POST /api/problems/[problemId]/tutor` under the existing Next.js server boundary. Run/Submit, judging, saved progress, notes, Neon schema, and Electron native permissions keep their existing behavior.
- Plan for the official server-side `openai` SDK, a small safe Markdown renderer for chat, an explicit server model setting, and production tracing for authored problem text. No credentials belong in client code or desktop packages.
- Add tests for zero tutor/provider calls during editing or panel lifecycle, exact source captured at Send, server context filtering, cancellation/failure recovery, auth, and responsive/browser/Electron behavior.
- The user approved implementation on 2026-11-14 using the existing local API key, hint-first guidance and session-only chat. Actual implementation and verification evidence is recorded in [the feature brief](../../../docs/features/problem-ai-tutor.md); no database migration is required.
